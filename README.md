# Köp 📝

[![License MIT](https://img.shields.io/badge/license-MIT-lightgrey.svg?style=flat)](https://github.com/peterhellberg/kop#license-mit)

A small example of [oto](https://github.com/pacedotdev/oto)-style RPC code generation (using the dependency-free generator in `./gen`) in the form of a shopping list CLI.

## Installation

```sh
go install github.com/peterhellberg/kop/cmd/...@latest
```

(This will install two binaries, `kop` and `kop-server`)

## Usage

Run `kop-server` in one terminal (this will by default start a web server on `localhost:12432`)

> [!NOTE]
> If you change the `PORT` for `kop-server`, then you will have to set the `KOP_ENDPOINT` variable accordingly.
>
> (Default is `http://localhost:12432/rpc/`)

Then run `kop Eggs Milk Flour` to create an initial list using the command line interface.

```md
 - EGGS
 - FLOUR
 - MILK
```

> [!IMPORTANT]
> If you speak Swedish, then you will want to `alias köp='kop'` (and if not, then you might want to `alias buy='kop'`)

You can then remove an item from the list by calling `kop no Eggs`

```md
 - FLOUR
 - MILK
```

If you do not want to use the cli then you can use [cURL](https://curl.se) directly

```sh
curl -d '{}' localhost:12432/rpc/List.Items
```
```json
{
  "items": [
    "FLOUR",
    "MILK"
  ]
}
```

And even add something else to the list 🍺

```sh
curl -d '{"items": ["Beer"]}' localhost:12432/rpc/List.Add
```
```json
{
  "items": [
    "BEER",
    "FLOUR",
    "MILK"
  ]
}
```

And when you want to start a new list then just run `kop nothing`

## Code generation

The RPC code is generated by the [gen](gen) package, which only depends on the Go standard library.

```go
func RPC(w io.Writer, pkg string, services ...reflect.Type) error
```

Each service is an interface type whose methods have the form `Method(Request) Response`,
where `Request` and `Response` are structs. `RPC` writes package `pkg` to `w`, containing:

- A `Service` interface with the methods as `Method(context.Context, Request) (*Response, error)`
- `RegisterService` for adding an implementation to a `Server`, which handles `POST {Basepath}Service.Method`
- A `ServiceClient` calling the same endpoints using an `RPC` (endpoint and `*http.Client`)
- A copy of every struct reachable from the methods, with JSON tags
- An `Error string` field (`json:"error,omitempty"`) on each response struct

JSON field names are the Go field names with the leading capital or initialism lowercased
(`Items` → `items`, `ID` → `id`, `HTTPServer` → `httpServer`), unless the field has a `json` tag,
which is then used as is.

The types are read using [reflect](https://pkg.go.dev/reflect), so the definitions package must be
imported by the program calling `gen.RPC`. For kop this is [internal/generate](internal/generate/main.go):

```go
gen.RPC(buf, "rpc", reflect.TypeFor[definitions.List]())
```

Regenerate [rpc/gen.go](rpc/gen.go) by running:

```sh
go generate ./...
```

The generated code is tested in [gen/internal/rpctest](gen/internal/rpctest), which is generated
from the fixture in [gen/internal/rpctest/defs](gen/internal/rpctest/defs/defs.go) by the same
`go generate ./...`. Its tests run the generated server and client against each other, and
(together with a test in [internal/generate](internal/generate)) check that both `rpctest/gen.go`
and `rpc/gen.go` are up to date:

```sh
go test ./...
```

> [!NOTE]
> `gen` does not validate the definitions; anything it cannot express results in generated code that does not compile.
> Doc comments are not carried over, and types from other packages (such as `time.Time`) are not supported.
